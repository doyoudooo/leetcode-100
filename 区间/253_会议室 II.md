给你一个会议时间安排的数组 `intervals` ，每个会议时间都会包括开始和结束的时间 `intervals[i] = [start_i, end_i]` ，返回 *所需会议室的最小数量* 。

**示例 1：**

```
输入：intervals = [[0,30],[5,10],[15,20]]
输出：2
解释：
需要两个会议室：
会议室 1：[0,30]
会议室 2：[5,10], [15,20] 
```

**示例 2：**

```
输入：intervals = [[7,10],[2,4]]
输出：1
```

**提示：**

*   `1 <= intervals.length <= 10^4`
*   `0 <= start_i < end_i <= 10^6`

---

## 解决方法

### 1. 问题理解

**目标：** 计算同时进行的最大会议数量，这等同于所需的最小会议室数量。
**输入：** 一个区间列表 `intervals`，代表会议的起止时间。
**输出：** 一个整数，表示所需的最小会议室数量。

### 2. 思路分析

#### 方法一：排序 + 最小堆 (优先队列)

这个方法模拟了会议室分配的过程。

1.  **排序：** 将所有会议按照**起始时间 `start_i`** 升序排序。
2.  **维护结束时间堆：** 使用一个最小堆 (Min-Heap) 来存储当前正在使用的会议室的**结束时间**。堆顶是所有正在进行的会议中最早结束的时间。
3.  **遍历会议：** 按照起始时间顺序遍历排序后的会议 `[start, end]`：
    - **检查是否有空闲会议室：** 查看堆顶元素（最早结束时间 `earliest_end`）。如果堆不为空，并且当前会议的起始时间 `start` **大于等于** `earliest_end` (`start >= earliest_end`)，说明最早结束的那个会议室已经空闲了，可以复用。
        - **复用会议室：** 将堆顶元素弹出 (`heapq.heappop(min_heap)`)，表示该会议室被释放。
    - **分配会议室：** 无论是否复用了会议室，当前会议都需要一个会议室。将当前会议的**结束时间 `end`** 加入堆中 (`heapq.heappush(min_heap, end)`)，表示这个会议室被占用，直到 `end` 时刻才可能空闲。
4.  **返回结果：** 遍历完所有会议后，堆的大小 `len(min_heap)` 就代表了在整个过程中同时使用的最大会议室数量，也就是所需的最小会议室数量。

**为什么这个方法有效？**
- 堆中存储的是当前被占用的会议室的结束时间。
- 当一个新会议开始时，我们检查是否有会议室在它开始前或开始时结束。最小堆的堆顶恰好告诉我们最早结束的那个会议室的时间。
- 如果有空闲的（`start >= earliest_end`），我们就复用它（弹出旧的结束时间，压入新的结束时间）。
- 如果没有空闲的（`start < earliest_end`），我们就必须增加一个新的会议室（直接压入新的结束时间）。
- 堆的大小始终跟踪着当前并发进行的会议数量，其最大值（即遍历结束时的堆大小）就是峰值并发数，即所需的最少会议室数。

#### 方法二：扫描线 (差分数组思想)

将每个会议看作两个事件：一个在 `start_i` 时刻的“开始”事件，和一个在 `end_i` 时刻的“结束”事件。

1.  **创建事件点：** 创建一个列表 `events`。对于每个区间 `[start, end]`，添加两个事件：`(start, +1)` 表示会议开始，需要一个会议室；`(end, -1)` 表示会议结束，释放一个会议室。
2.  **排序事件点：** 对 `events` 列表进行排序。主要按时间排序，如果时间相同，**让“结束”事件排在“开始”事件之前**。这很重要，确保在同一时间点，先处理释放会议室的操作，再处理需要会议室的操作，这样可以正确计算峰值。
    - 排序规则：`key=lambda x: (x[0], x[1])`。因为 `-1 < +1`，所以结束事件会排在开始事件之前。
3.  **扫描计算：** 初始化当前所需会议室数量 `current_rooms = 0` 和最大所需会议室数量 `max_rooms = 0`。遍历排序后的 `events`：
    - 对于每个事件 `(time, type)`，更新 `current_rooms += type`。
    - 更新 `max_rooms = max(max_rooms, current_rooms)`。
4.  **返回结果：** 遍历结束后，`max_rooms` 就是所需的最小会议室数量。

**为什么这个方法有效？**
- 通过将区间转换为时间点上的事件，我们可以模拟时间流逝过程中会议室数量的变化。
- `+1` 代表需要增加一个房间，`-1` 代表可以减少一个房间。
- 按时间顺序处理这些事件，`current_rooms` 准确地反映了在任何给定时间点之后、下一个事件发生之前，同时进行的会议数量。
- `max_rooms` 记录了这个过程中的峰值，即所需的最少会议室数。

### 3. 代码实现 (Python)

#### 方法一：排序 + 最小堆

```python
import heapq
from typing import List

class Solution:
    def minMeetingRooms_heap(self, intervals: List[List[int]]) -> int:
        """
        使用排序 + 最小堆计算最小会议室数量。
        """
        if not intervals:
            return 0
            
        # 1. 按起始时间排序 O(N log N)
        intervals.sort(key=lambda x: x[0])
        
        # 2. 最小堆存储结束时间
        min_heap = [] # Stores end times of rooms currently in use
        
        # 3. 遍历会议
        for start, end in intervals:
            # 检查是否有空闲会议室 (最早结束的那个是否已结束)
            if min_heap and start >= min_heap[0]:
                # 复用会议室，弹出最早结束的时间
                heapq.heappop(min_heap)
                
            # 分配会议室 (无论是新开还是复用)，加入当前会议的结束时间
            heapq.heappush(min_heap, end)
            
        # 4. 堆的大小即为所需的最大会议室数量
        return len(min_heap)

```

#### 方法二：扫描线

```python
from typing import List

class Solution:
    def minMeetingRooms(self, intervals: List[List[int]]) -> int:
        """
        使用扫描线方法计算最小会议室数量。
        """
        if not intervals:
            return 0
            
        # 1. 创建事件点 O(N)
        events = []
        for start, end in intervals:
            events.append((start, 1))  # 会议开始
            events.append((end, -1))   # 会议结束
            
        # 2. 排序事件点 O(N log N)
        # 按时间排序，时间相同则结束事件 (-1) 在前
        events.sort() 
        # 或者显式指定 key: events.sort(key=lambda x: (x[0], x[1]))
        
        # 3. 扫描计算 O(N)
        current_rooms = 0
        max_rooms = 0
        for _, type in events:
            current_rooms += type
            max_rooms = max(max_rooms, current_rooms)
            
        return max_rooms

```

### 4. 复杂度分析

- **方法一 (堆)：**
    - 时间复杂度：O(N log N)。排序 O(N log N)，堆操作总共 O(N log N) (每个元素最多进堆出堆一次)。
    - 空间复杂度：O(N)。最坏情况下，所有会议都重叠，堆的大小为 N。
- **方法二 (扫描线)：**
    - 时间复杂度：O(N log N)。创建事件 O(N)，排序 O(2N log 2N) = O(N log N)，扫描 O(N)。
    - 空间复杂度：O(N)。需要存储 N 个开始事件和 N 个结束事件。
