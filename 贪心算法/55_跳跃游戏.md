给你一个非负整数数组 `nums` ，你最初位于数组的 **第一个下标** 。数组中的每个元素代表你在该位置可以跳跃的最大长度。

判断你是否能够到达最后一个下标。

**示例 1：**

```
输入：nums = [2,3,1,1,4]
输出：true
解释：可以先跳 1 步，从下标 0 到达下标 1, 然后再从下标 1 跳 3 步到达最后一个下标。
```

**示例 2：**

```
输入：nums = [3,2,1,0,4]
输出：false
解释：无论怎样，总会到达下标为 3 的位置。但该下标的最大跳跃长度是 0 ， 所以永远不可能到达最后一个下标。
```

**提示：**

*   `1 <= nums.length <= 10^4`
*   `0 <= nums[i] <= 10^5`

## 解决方法

### 1. 问题理解

**目标：** 判断从数组的第一个位置（索引 0）出发，是否能够到达数组的最后一个位置（索引 `n-1`）。
**规则：** 在索引 `i` 处，最多可以向前跳 `nums[i]` 步，即可以跳到 `[i, i + nums[i]]` 范围内的任意位置。
**输入：** 非负整数数组 `nums`。
**输出：** `True` 或 `False`。

### 2. 思路分析 (贪心算法)

我们可以使用贪心策略来解决这个问题。核心思想是维护一个变量 `max_reach`，表示从起点（索引 0）出发，**当前能够到达的最远位置的索引**。

**算法流程：**
1.  **初始化：**
    - `max_reach = 0`。表示初始时只能到达索引 0。
    - `n = len(nums)`。数组长度。
2.  **遍历数组：** 遍历数组 `nums`，索引从 `i = 0` 到 `n - 1`。
    - **检查可达性：** 在遍历到索引 `i` 时，首先检查当前位置 `i` 是否是可达的。如果 `i > max_reach`，说明从起点无论如何都无法跳到当前位置 `i`，因此也就不可能到达更远的终点。直接返回 `False`。
    - **更新最远可达距离：** 如果当前位置 `i` 是可达的 (`i <= max_reach`)，那么从位置 `i` 出发，可以跳到的最远距离是 `i + nums[i]`。我们需要更新全局的 `max_reach`，取当前 `max_reach` 和 `i + nums[i]` 中的较大值。即 `max_reach = max(max_reach, i + nums[i])`。
    - **提前结束判断 (可选优化)：** 如果在某一步 `max_reach` 已经大于或等于 `n - 1`，说明已经可以到达终点，可以直接返回 `True`。
3.  **返回结果：** 如果循环正常结束（即没有因为 `i > max_reach` 而提前返回 `False`），说明数组中的每个位置（包括最后一个位置 `n-1`）都是可达的（或者说，`max_reach` 最终覆盖了 `n-1`）。返回 `True`。

**为什么这个贪心策略有效？**
- 我们一步一步地向前探索，`max_reach` 记录了我们探索能力的边界。
- 在每一步 `i`，我们都利用当前位置 `i` 的跳跃能力 `nums[i]` 来尝试扩展这个边界 (`max_reach`)。
- 如果在某一步 `i`，发现 `i` 本身就超出了之前的边界 `max_reach`，说明我们已经无法前进了，终点自然也无法到达。
- 只要我们能一直前进，并且 `max_reach` 最终能覆盖或超过终点 `n-1`，就说明终点是可达的。

### 3. 代码实现 (Python - 贪心)

```python
from typing import List

class Solution:
    def canJump(self, nums: List[int]) -> bool:
        """
        使用贪心算法判断是否能到达最后一个下标。
        """
        n = len(nums)
        max_reach = 0 # 当前能到达的最远索引
        
        for i in range(n):
            # 如果当前索引 i 超过了之前能到达的最远距离，说明无法到达 i，更无法到达终点
            if i > max_reach:
                return False
            
            # 更新从索引 0 出发能到达的最远距离
            max_reach = max(max_reach, i + nums[i])
            
            # 优化：如果最远距离已经覆盖了终点，提前返回 True
            if max_reach >= n - 1:
                return True
                
        # 如果循环正常结束，说明可以到达终点（或只有一个元素的情况）
        # 实际上，由于上面的优化，如果能到达，循环会提前结束并返回 True。
        # 如果循环结束还没返回 True，只有一种可能：n=1 且 nums[0]=0，此时 max_reach=0, n-1=0，满足条件，已在循环内返回 True。
        # 或者无法到达的情况，已在循环内返回 False。
        # 所以理论上这里可以不写，但为了逻辑完整性或处理特殊边界，可以保留。
        # 考虑到循环条件是 range(n)，如果能到达 n-1，循环会在 i=n-1 时结束或提前结束。
        # 如果循环结束，说明 i 成功遍历到了 n-1，并且没有触发 i > max_reach。
        # 这意味着 max_reach 至少是 n-1。所以返回 True 是正确的。
        return True 
        # 更严谨的写法是检查循环结束时 max_reach >= n - 1，但根据逻辑推导，循环能正常结束就意味着可以到达。
```
